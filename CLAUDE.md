### 1.4 Backend API (reuse as is)
- Declared in `api/ApiServices.kt`, `api/UserApiServices.kt` (≈122 endpoint annotations; repository in `api/ApiRepository.kt`). Resource families: `oauth/token`, `oauth/revoke`; `current_session/*` (session_info, register_device_token, revoke_device_token, sendbird_token, pending_actions, stats_summary, player_cards, mark_card_as_clicked, user_setting, update_user_setting, update_time_zone, update_text_consent, user_feedbacks, my_favourite_places, link_playstore_subscription, api_audit_logs, setup_default_chat_rooms); `resources/*` (metadata, messages, pre_login_messages, event_participants_status_filter_options); `reference_data` (+ `scoring_formats`); `settings/enable_google_analytics|enable_mixpanel_analytics`; `verifications/send_sms_code|verify_sms_code`; `validations/*`; `users` (+ `{id}`, profile, roles, reminder preferences, change_mobile_number, destroy_profile_image, mark_as_signed_up); `teams` (+ team_players, rankings, points histories, archive/unarchive, inactivate/reactivate); `events` (+ event_participants accept/decline/rejoin/leave/join_waitlist/update_rsvp_preference, event_matches, event_rounds, schedule_options, update_*/assign_*/pick_players/add|remove_participants, cancel/reschedule/confirm_schedule, mark_winner, accept_scores, update_scores, chat room setup); `schedule/{drafts,scheduled_events,to_be_scheduled}`; `places` (+ courts, by_location, favourites); `chat_rooms`; `timezone_infos/lookup`; `user_feedbacks`.
- **The annotation files are the contract. Re-read them per endpoint**; many paths repeat with different query maps, so query params/body shapes must be taken from `ApiServices.kt` and `models/**` (requests under `models/events/requests`, responses under `models/events/responces` [sic]).
- **Headers on every authenticated call** (`TokenInterceptor`): `Authorization: Bearer <access_token>`, `Accept: <ace_api_version from environment.xml>` (API versioning via Accept header), `app-version: <versionName>`, `Accept-Language: <device locales>`.
- **Auth:** OAuth2 password/refresh style via `oauth/token` with a client id/secret from `environment.xml` and `FormRefreshToken` (refresh grant type string resource). Session JSON (`SessionToken` incl. `accessToken`, `refreshToken`, `expiresIn`, `createdAt`, `user.uid/uuid`) is stored in SharedPreferences (`SESSION_TOKEN`; `SharedPrefUtils` imports EncryptedSharedPreferences, whether the token store is actually encrypted is **[UNVERIFIED]**).
- **Refresh behavior to reproduce:** proactive refresh when `createdAt+expiresIn <= now` (only after sign-up completed); on 401 refresh then retry once; `TokenAuthenticator` also refreshes (synchronized); refresh 401 is retried until `MAX_UNAUTHORISED_API_CALLS_COUNT = 5` then forced logout; refresh 400 → immediate forced logout (`appUnauthorisedLogout`). Known weaknesses (shared mutable flags `isTokenRefreshing`, recursion) — implement a single-flight refresh in Dart instead of copying them, but preserve the observable semantics.
- **Serialization:** Gson with `LOWER_CASE_WITH_UNDERSCORES` field naming (snake_case JSON), plus a `StringConverterFactory` for raw string bodies. Dispatcher `maxRequests=3`; connect/read/write timeout 30 s. Session-info response drives subscription/trial/permission state (`userSession.hasFullFeatureAccess`, `trialRemainingDays`, `subscribedDeviceType`, `userPermissions`, `appSubscription.purchaseTokens`).
- Pagination, error and date formats: product decision is to **follow standard mobile-app conventions**. Observed on iOS: list endpoints take `page` and `per_page` query params (page sizes 10/20/100 in `IntegerConstant.swift`); error bodies decode `error`, `message`, `error_message` (`ServiceError.swift`). Implement a tolerant `ServerErrorDto` reading all three keys, 1-based paging with a `PagedResult` helper (load-more on scroll, pull-to-refresh, stop when a page returns fewer than `per_page` items unless a response carries total/pagination metadata — check the model for that endpoint), and ISO-8601/UTC dates unless a model proves otherwise. Multipart uploads (profile/chat images; Android compresses with `id.zelory:compressor`) follow the same 'verify per endpoint' rule. Offline/timeout/cancel errors must not be reported to the crash tool (iOS `shouldReportError` filters them).
- Current client logs full HTTP bodies (`HttpLoggingInterceptor.BODY`) and ships Chucker in non-production; the Flutter client must not log tokens/PII.

## 3. Architecture — Clean Architecture + MVVM, screen-first

Dependency direction (enforce in review and with an import-lint such as `custom_lint`/`import_lint`):

```
screen widgets → ViewModel (Riverpod Notifier) → use cases → repository contracts
                                                       ↑ implemented by
                              repository impls → data sources (Retrofit/Dio, local) → DTOs/mappers
```
- Widgets never touch Dio/Retrofit/storage/billing. ViewModels never import `package:flutter/widgets.dart` UI types (except `AsyncValue`-style state). Domain (use cases + contracts + entities) imports no Flutter, Dio or Retrofit.
- `screens/<a>/` may import `common/` and (rarely, via an explicit public file) another screen's `models/`; **`common/` must never import `screens/`**. No circular imports. If two screens need the same thing, move it to `common/`.

### 3.1 Folder structure (derive actual screens from §1.3; do not create empty folders)
```
lib/
  main.dart                 # per-flavor entrypoints: main_dev.dart, main_qa.dart, main_prod.dart ...
  app/  app.dart  bootstrap.dart  router/  theme/  localization/  config/  (brand + environment)
  screens/
    login/ | signup/ | splash/ | home/ | schedule/ | create_event/ | teams/ | location/
    chats/ | subscriptions/ | settings/ | profile/ | app_update/ | ...
      <screen>_screen.dart  <screen>_view_model.dart  <screen>_state.dart  <screen>_test_ids.dart
      models/ widgets/ usecases/ repositories/ data_sources/           # only when needed
  common/
    widgets/ models/ usecases/ repositories/ data_sources/{remote,local}/
    network/ storage/ errors/ accessibility/ utils/ extensions/
    notifications/ billing/ analytics/                                   # app-wide capabilities
  l10n/  app_en.arb
```
Large multi-step flows (create event, signup) are a **screen group**: `screens/create_event/` with one subfolder per step (`steps/event_court/…`) and a shared flow ViewModel. **Tests live under `test/` mirroring `lib/`** (`test/screens/<screen>/…_test.dart`, `test/common/…`), the Flutter default that keeps `flutter test`, coverage and lints working (test code inside `lib/` triggers `depend_on_referenced_packages` and ships with the app). Shared fakes/fixtures live in `test/support/` and `test/fixtures/`.

Naming: `snake_case.dart`; `XScreen`, `XViewModel`, `XState` (immutable, `freezed`-free unless adopted project-wide), `XUseCase` (callable class `call()`), `XRepository` (abstract) / `XRepositoryImpl`, `XRemoteDataSource`, `XDto` + `toDomain()`.

### 3.2 State, errors, navigation
- Riverpod for DI and state; state classes are immutable and explicitly model `loading | data | empty | error`. Use `ref.watch` in widgets, `ref.read` in callbacks; providers declared next to their screen; app-wide providers in `common/` or `app/`.
- One `AppFailure` hierarchy in `common/errors/` mapping timeout, offline, HTTP status (401 handled by auth layer), parse errors. User-facing text via l10n keys.
- **go_router** only; route table in `app/router/`; route names/params documented in `app/router/routes.md` (create when first routes exist). `redirect` handles auth/session restore, forced update, downtime, root-detection blocks. Auth state is a Riverpod `Listenable` for `refreshListenable`. Fallback: unknown route → home (signed in) or welcome (signed out). No `Navigator.push` scattered in widgets.

## 4. API integration rules
- Retrofit (declarative) over Dio (transport); one `ApiClient` configured in `common/network/` with: base URL by environment, `Accept` version header, `app-version`, `Accept-Language`, bearer injection, single-flight refresh + one retry on 401, forced-logout rules from §1.4, timeouts (30 s connect/read/write unless backend says otherwise), CA-level TLS pinning per §4.1, a redacting logger (debug only; never tokens/PII). **Built (2026-10-27):** the in-app network inspector (native `Chucker`) is `alice`/`alice_dio` (`common/network/network_inspector.dart`), attached per Dio client in `_baseDio` (`common/auth/auth_providers.dart`) for every non-production environment, same as native — never for `production`, release build or not. Its own interceptor is added before `AuthInterceptor` puts the bearer token on the request, and `AliceConfiguration.redactedHeaders` also redacts it directly (unlike chucker_flutter, which was tried first and has no redaction of its own — reverted for this reason plus being less recently maintained). Alice's own floating, draggable overlay bubble (`AliceConfiguration.showOverlayBubble: true`, shown once `app.dart`'s `RacketmatesApp` builds, via a post-frame callback on `networkInspector?.showOverlayBubble()`) is the entry point, in place of its shake-gesture trigger (`showInspectorOnShake: false` — awkward on a desktop simulator and native has no shake affordance either). **`alice`'s `permission_handler_android` dependency compiles against `compileSdk 37`, above this project's `compileSdk = flutter.compileSdkVersion` default (36)**: confirmed by a real `flutter build apk --debug --flavor dev` failure. Decided (2026-10-27) to raise `android/app/build.gradle.kts`'s `compileSdk` to a hardcoded `37` rather than keep chucker_flutter — Android/Flutter's own guidance is that this is backward compatible, and the build (Android debug + iOS simulator) was re-verified afterward. **Risk to flag if CI ever runs this:** CI's Android SDK installation needs platform 37 available.
- Request/response models are `json_serializable` with explicit `@JsonKey(name: ...)` matching the exact snake_case keys, nullability and enum string values from the Kotlin models. Keep date/time formats identical to what Gson parsed (check each model).
- Retrofit interfaces live in the owning screen's `data_sources/` (or `common/data_sources/remote/` if used by ≥2 screens, e.g., `current_session/*`, `reference_data`).
- Contract tests: fixtures in `test/fixtures/api/<endpoint>.json`, captured from Android behavior/QA environment with PII scrubbed, asserted through `DioAdapter` mocks; no live calls in CI.
- Generated code: `dart run build_runner build --delete-conflicting-outputs`; generated `*.g.dart` are committed or CI-generated consistently (decide once; document).

### 4.1 TLS pinning (decided: pin CA public keys, not the leaf)
Strategy adapted from the team's SSL pinning change summary; full detail, pins, tests and rotation in the Flutter repo's `docs/ssl-pinning.md`.
- Pin the issuing CA public keys (SPKI SHA-256): primary intermediate (Sectigo DV R36 `a9khLOZJ…`), backup intermediate (Sectigo DV E36 `ZSagvDzj…`) and root (Sectigo Root R46 `Douxi77v…`). Accept when the validated chain ends at any pin. A normal renewal needs no app release.
- Verified 2026-10-22: production, hotfix, qa, regression and Feature1 hosts (`*.racketmatesapp.com`) all serve leaf > R36 > R46. Pinned envs: production, hotfix, qa, regression, staging; dev/local unpinned.
- Dart's `HttpClient` ignores Android `network_security_config` pin-sets and iOS `NSPinnedDomains`, and Dio hooks cannot express CA pinning, so the API Dio uses `SecurityContext(withTrustedRoots: false)` with the three bundled CA PEMs (`lib/common/network/ssl_pinning.dart`). CA/intermediate anchoring verified on the Dart VM; **Android/iOS device verification is still required** (negative test, root-only on minimum OS, MITM proxy).
- Guardrails: never pin a leaf; pin changes ship in an app release before the server changes CA; `tool/verify_ssl_pins.sh` (also in the `quality` lane) keeps constants and PEMs in sync; offline tests cover intermediate-only, root-only and wrong-CA rejection.
- **Native apps today pin the production leaf** (Android `fingerprint_one` = leaf SPKI; iOS bundles the leaf `racketmates.der`) and the production leaf expires **2026-12-12**; unless it is reissued with the same key they will fail TLS at renewal. Decision: native apps are **not** changed as part of this work; this is recorded as an operational risk for the native owners and as a reason the Flutter release should not depend on the native pins.
